# Как устроен бот: разбор кода

Этот файл для тебя: здесь простыми словами объяснено, что делает каждая часть проекта.
README.md (на английском) предназначен для заказчиков на GitHub.

---

## Общая схема

```
Пользователь пишет боту
        │
        ▼
     bot.py  ──── запускает бота, подключает роутеры
        │
        ▼
handlers/user.py  ─┐   обработчики: «что делать, когда пришло такое-то сообщение / нажата кнопка»
handlers/admin.py ─┘
        │  используют
        ▼
database.py (данные)   keyboards.py (кнопки)   texts.py (тексты)   states.py (шаги диалогов)
        │
        ▼
     config.py  ──── настройки из .env
```

Главная идея: **каждый файл отвечает за одно**. Тексты не перемешаны с логикой, SQL не перемешан с кнопками. Так код проще читать, а заказчику проще что-то поменять.

---

## config.py: настройки

- `load_dotenv()` читает файл `.env` и кладёт значения в переменные окружения.
- `os.getenv("BOT_TOKEN")` достаёт оттуда токен. Токен **нельзя** писать прямо в код: если залить его на GitHub, бот может угнать кто угодно. Поэтому `.env` указан в `.gitignore`, а на GitHub лежит только шаблон `.env.example`.
- `ADMIN_ID` превращаем в `int`, потому что Telegram присылает ID пользователя числом.
- `ORDER_STATUSES` содержит все статусы заказа. `ADMIN_STATUSES = ORDER_STATUSES[1:]` означает «все, кроме `new`»: статус `new` ставится автоматически, а остальные админ выбирает кнопками.
- Если токена нет, бот сразу падает с понятной ошибкой, а не со странной где-то в глубине aiogram.

## texts.py: все тексты

- `TEXTS` — словарь словарей: `TEXTS["en"]["btn_cart"]` → `"🛒 Cart"`, `TEXTS["uk"]["btn_cart"]` → `"🛒 Кошик"`.
- `t(lang, key, **kwargs)` — главная функция. Берёт текст на нужном языке и подставляет значения в `{фигурные скобки}`:
  `t("en", "added_to_cart", name="Latte", qty=2)` → `"✅ Added to cart: Latte × 2"`.
  Если ключа нет в каком-то языке, берётся английский вариант (язык по умолчанию).
- `variants("btn_cart")` возвращает `{"🛒 Cart", "🛒 Кошик"}`. Это нужно, потому что кнопки главного меню (reply-клавиатура) присылают боту **обычный текст**. Бот должен понять нажатие на любом языке.
- `price(3.5)` → `"$3.50"`: единый формат цены по всему боту.
- `format_items(...)` превращает список товаров в строки `• Latte × 2 = $7.80` для подтверждения заказа, истории и уведомления админу.
- В текстах используется HTML-разметка (`<b>жирный</b>`, `<i>курсив</i>`), потому что в bot.py включён `ParseMode.HTML`.

## states.py: состояния FSM

FSM (finite state machine, «конечный автомат») — способ вести **пошаговый диалог**.
Когда бот спросил «Как вас зовут?», он должен запомнить, что следующее сообщение — это имя, а не что-то другое.

- `OrderForm`: оформление заказа (name → phone → address → comment → confirm).
- `AddProduct`: добавление товара админом (категория → название → описание → цена → фото).
- `Broadcast`: рассылка (сообщение → подтверждение).

Как это работает в коде:
- `await state.set_state(OrderForm.phone)` — «теперь ждём телефон»;
- `await state.update_data(name=name)` — сохранить ответ во временное хранилище;
- `await state.get_data()` — достать все ответы;
- `await state.clear()` — выйти из диалога и всё забыть.

## database.py: база данных

Используется **SQLite**: база — это просто файл `shop.db`, сервер устанавливать не нужно. **aiosqlite** позволяет работать с ней асинхронно, чтобы бот не «замирал», пока идёт запрос к базе.

**Таблицы:**
| Таблица | Что хранит |
|---|---|
| `users` | все пользователи и их язык (нужно для рассылки и статистики) |
| `categories` | категории (название + эмодзи) |
| `products` | товары: категория, название, описание, цена, эмодзи, фото |
| `cart` | корзины: кто, какой товар, сколько штук |
| `orders` | заказы: клиент, имя, телефон, адрес, комментарий, сумма, статус, дата |
| `order_items` | товары внутри заказа |

**Важные моменты:**
- В `order_items` хранится **копия** названия и цены, а не ссылка на товар. Если админ потом удалит товар или поменяет цену, история заказов не сломается.
- `_fetchall`, `_fetchone`, `_execute` — маленькие помощники, чтобы не повторять в каждой функции «открыть соединение → выполнить → закрыть».
- `db.row_factory = aiosqlite.Row` позволяет обращаться к строкам по имени столбца: `row["price"]` вместо `row[3]`.
- Знаки `?` в запросах — **параметры**. Значения никогда не вклеиваются в SQL строкой, это защищает от SQL-инъекций.
- **Миграция.** Колонку `comment` добавили, когда у тебя уже была база с заказами. `CREATE TABLE IF NOT EXISTS` не меняет существующую таблицу, поэтому `init_db()` через `PRAGMA table_info(orders)` проверяет, есть ли колонка, и если нет, добавляет её через `ALTER TABLE ... ADD COLUMN`. Старые заказы остаются, у них комментарий просто пустой (`NULL`). Так же в реальных проектах обновляют базу без потери данных.
- `init_db()` создаёт таблицы (`CREATE TABLE IF NOT EXISTS` значит «создать, если её ещё нет»). Если категорий нет, добавляет демо-каталог `DEMO_CATALOG`: 3 категории по 3 товара с фото с Unsplash.
- `add_to_cart` использует `INSERT ... ON CONFLICT DO UPDATE`: если товар уже в корзине, количество увеличивается, а не создаётся дубль.
- `create_order` за одно соединение берёт корзину, считает сумму, создаёт заказ, копирует товары и очищает корзину. `commit()` в конце сохраняет **всё сразу**: если где-то случится ошибка, не получится «заказ создан, а корзина не очищена».
- `get_stats` считает выручку через `CASE WHEN status != 'cancelled'`: отменённые заказы в выручку не идут.

## keyboards.py: кнопки

Бывает два вида клавиатур:
- **Reply-клавиатура** — кнопки под полем ввода (главное меню, «Share phone number»). При нажатии бот получает обычный текст.
- **Inline-клавиатура** — кнопки прямо под сообщением. При нажатии бот получает `callback_data`, невидимую строку с данными.

**CallbackData-классы** (`QtyCB`, `CartCB`, `AdminCB` и др.) упаковывают данные в короткую строку и распаковывают обратно:
`QtyCB(action="inc", product_id=5, category_id=1, qty=2)` ⇄ `"qty:inc:5:1:2"`.
Без них пришлось бы вручную писать `data.split(":")`. Telegram ограничивает callback_data 64 байтами, поэтому передаём только ID, а не названия.

- `InlineKeyboardBuilder` / `ReplyKeyboardBuilder` — удобный способ собрать клавиатуру; `adjust(2)` = по 2 кнопки в ряду.
- `request_contact=True` делает кнопку «Share phone number»: Telegram сам отправит номер пользователя.
- `NOOP` — кнопки-«надписи» (например, «2 pcs» между ➖ и ➕). Нажатие на них ничего не делает.
- В `order_status_kb` текущий статус отмечается точкой `•`, чтобы админ сразу видел, что выбрано.

## handlers/user.py: всё для клиента

**Роутер** (`router = Router()`) — набор обработчиков. Декоратор `@router.message(...)` говорит: «вызывай эту функцию, когда пришло сообщение, подходящее под фильтр».

Фильтры, которые используются:
- `CommandStart()`, `Command("cancel")` — команды;
- `F.text.in_(variants("btn_catalog"))` — текст равен одной из надписей кнопки;
- `OrderForm.name` — пользователь сейчас на шаге «имя»;
- `F.contact` — пользователь прислал контакт;
- `kb.QtyCB.filter(F.action == "add")` — нажата inline-кнопка с такими данными.

**Разделы файла:**
1. **Помощники.** `safe_delete` удаляет сообщение без падения (Telegram не даёт удалять сообщения старше 48 часов). `show_screen` меняет «экран»: текстовое сообщение редактируется, а сообщение с фото удаляется и отправляется новое, потому что фото нельзя превратить в текст через редактирование.
2. **/start и язык.** /start сохраняет пользователя и показывает кнопки языков. При выборе языка он записывается в базу, и приходит приветствие «Hi!» / «Привіт!» **без имени**, как ты и просил. `/cancel` и кнопка «❌ Cancel» работают в любом состоянии: сбрасывают диалог и возвращают меню.
3. **Каталог.** Категории → список товаров → карточка. `send_product_card` пытается отправить фото; если ссылка битая, отправляет текст с эмодзи-заглушкой. После первой успешной отправки Telegram выдаёт `file_id` фото, и мы сохраняем его в базу вместо ссылки: следующие отправки мгновенные и не зависят от чужого сайта.
4. **Количество в карточке.** ➕/➖ меняют только клавиатуру (`edit_reply_markup`), фото и текст остаются. Текущее количество хранится прямо в callback_data кнопок, поэтому базу трогать не нужно. «Add to cart» добавляет товар и показывает всплывающее уведомление (`callback.answer(текст)`).
5. **Корзина.** `render_cart` собирает текст и кнопки из базы. Любое действие (➕, ➖, 🗑, очистить) меняет базу, после чего корзина перерисовывается.
6. **Оформление (FSM).** Имя (проверка длины) → телефон (кнопка-контакт **или** ручной ввод с проверкой регулярным выражением `PHONE_RE`) → адрес → комментарий → итоговое сообщение с кнопками ✅/❌.
   **Комментарий** необязательный: клиент пишет пожелания («2 кофе без сахара, 1 с мятным сиропом», «заберу под домом») или жмёт «⏭ Skip». Максимум 300 символов. `format_comment` из texts.py возвращает строку «💬 Comment: ...» или пустую строку, если комментария нет. Поэтому в шаблонах стоит просто `{comment}`, и лишней пустой строки не появляется. При подтверждении `create_order` превращает корзину в заказ, клиент получает номер заказа, а админ получает уведомление (`notify_new_order`).
   Кнопки подтверждения убираются сразу после нажатия: двойной клик не создаст два заказа. Если нажать старую кнопку, придёт «This button is no longer active».
7. **Мои заказы.** Последние 10 заказов с товарами, суммой и статусом.

`escape(...)` экранирует то, что ввёл пользователь. Если кто-то напишет имя `<b>`, без экранирования сломалась бы HTML-разметка сообщения.

## handlers/admin.py: всё для админа

```python
router.message.filter(F.from_user.id == ADMIN_ID)
router.callback_query.filter(F.from_user.id == ADMIN_ID)
```
Эти две строки — **защита**: все обработчики в файле срабатывают только для админа. Обычный пользователь на /admin просто не получит ответа (я это проверил тестом).

1. **Заказы и статусы.** `format_order` собирает полное описание заказа со ссылкой на профиль клиента. `notify_new_order` отправляет его админу с кнопками статусов. `change_status` меняет статус в базе, обновляет сообщение у админа и отправляет клиенту уведомление **на языке клиента**. `try/except` нужен на случай, если клиент заблокировал бота: тогда бот не упадёт.
2. **/admin** открывает панель с inline-кнопками. Все разделы открываются редактированием этого же сообщения, чтобы чат не захламлялся.
3. **Последние заказы.** Список из 10 последних и кнопки `#номер`: по нажатию заказ открывается с кнопками статусов.
4. **Статистика.** Пользователи, заказы, выручка, разбивка по статусам.
5. **Добавление товара (FSM).** Категория (кнопкой) → название → описание → цена (принимает и `3.50`, и `3,50`) → фото. Фото можно отправить картинкой (сохраняется её `file_id`), ссылкой или пропустить через `/skip`: тогда будет эмодзи категории.
6. **Удаление товара** с подтверждением «Yes, delete», чтобы не удалить случайно. Товар удаляется и из корзин покупателей.
7. **Рассылка.** Админ присылает любое сообщение, бот запоминает его ID и спрашивает подтверждение. Потом `copy_message` копирует его каждому пользователю, поэтому работают и текст, и фото, и видео. Пауза `0.05` секунды нужна из-за лимита Telegram (~30 сообщений в секунду). Если Telegram всё же просит подождать (`TelegramRetryAfter`), бот ждёт и повторяет. В конце показывается, скольким доставлено и скольким нет.

## bot.py: точка входа

1. `logging.basicConfig` включает логи в терминале: видно, что бот работает и какие ошибки возникают.
2. `db.init_db()` создаёт базу и демо-товары.
3. `Bot(...)` с `ParseMode.HTML` включает HTML-разметку во всех сообщениях по умолчанию.
4. `Dispatcher(storage=MemoryStorage())` — диспетчер, который распределяет входящие обновления по обработчикам. Состояния FSM хранятся в памяти: после перезапуска бота незаконченные диалоги сбросятся (для портфолио это нормально; в продакшене используют Redis).
5. `dp.include_routers(user.router, admin.router)` — **порядок важен**: роутер клиента идёт первым, чтобы `/cancel` срабатывал и во время админских диалогов.
6. `set_commands` задаёт меню команд в Telegram. Админ дополнительно видит `/admin` (через `BotCommandScopeChat`).
7. `delete_webhook(drop_pending_updates=True)` пропускает сообщения, которые пришли, пока бот был выключен.
8. `start_polling` — бот начинает постоянно спрашивать Telegram «есть новые сообщения?».

## Как бы я рассказал о проекте заказчику (шпаргалка)

> Telegram-бот интернет-магазина на aiogram 3 + SQLite: каталог с карточками товаров, корзина, пошаговое оформление заказа через FSM с комментарием к заказу, история заказов, два языка. Админ-панель прямо в Telegram: уведомления о заказах со сменой статуса (клиент получает уведомление), добавление и удаление товаров, статистика и рассылка. Код модульный: тексты, клавиатуры, база и обработчики разнесены по отдельным файлам.
